What is SiteVitals?

SiteVitals is a fast, passive hygiene audit for any website and any code repository. Most sites don't get hacked through exotic vulnerabilities — they fail on the basics: a missing HSTS header, a loose Content-Security-Policy, an expired certificate, no DMARC record, an API key committed to GitHub. Those misconfigurations are cheap to fix but invisible until someone looks, and a full security audit is slow, expensive overkill for a routine check.

SiteVitals covers that gap. Give it a URL and it checks the security basics — HTTPS redirect, security headers, cookie flags, TLS certificate and version, DNS records — then scores the site out of 100 with a grade and a plain-English fix for every failure. Point it at a local repo and it audits the working tree for leaked secrets, vulnerable dependencies, and injection-pattern risks, with its own separate 100-point repo score. Reports are self-contained HTML files: emailable, open offline, no dashboard needed.

Who it's for: site owners checking a launch or a migration, developers who want a pre-commit sanity check, and agents or CI pipelines that need a machine-readable score — the --json mode exists because the next consumer of a security report is just as likely to be an agent as a human.

What makes it different: one command, no setup; a score you can track over time, so "is the site healthier?" is answerable; fixes, not just findings; and every check is a passive read — no scans, no payloads, nothing that touches the target beyond asking it the same questions a browser would.

Built in-house, zero dependencies

The checking engine is written from scratch in TypeScript on Node.js — no shell-outs to gitleaks, semgrep, or osv-scanner, and zero runtime dependencies. Rule patterns are vendored as data (MIT Gitleaks defaults, attributed); the only network call is the OSV lookup. There is no supply chain to audit in the auditor.

URL mode — 18 passive checks, score = 100 minus failed weights:

Repo mode (sitevitals repo <path>) — its own 100-point score:

  • Secrets — vendored MIT Gitleaks rule patterns, redacted previews only, never verified live
  • Dependencies — OSV.dev lookups for npm, PyPI, and Go manifests; fix guidance picks the highest fixed version
  • Injection patterns — JS/TS regex checks (dynamic code execution, shell-from-input, SQL string building, unsanitized HTML)
  • Dockerfile — root user, secrets in ENV/ARG, unpinned base image
  • License audit — copyleft and unknown licenses in the npm tree
  • CI config — unpinned actions, write-all permissions in GitHub workflows
  • SBOM — --sbom emits a CycloneDX 1.5 inventory of the same manifests

Output: a human report card (self-contained HTML) plus --json for agents and CI. Report-only — it never changes the scanned repo.

How it works

CLI: URL or repo path→ Normalize + parallel checks (20s timeouts)→ Score: 100 − failed weights→ Console summary + HTML report (+ JSON)

Repo mode swaps in a tree walk (5,000-file / 1 MiB caps, allowlist support) and the check modules above. An error (timeout, DNS down, OSV unreachable) never counts as a vulnerability.

Run it

git clone https://github.com/ApoorvRusia/sitevitals.git
cd sitevitals
npm install && npm run build
node dist/cli.js https://example.com        # URL report card
node dist/cli.js repo /path/to/your/repo    # repo score

For agents

SiteVitals is agent-first. Give this repo's URL to an AI agent — Claude, Copilot, Muse, Grok — and it can take it from there: install, run audits on your websites and projects, and report back with scores and fixes.

  • AGENTS.md at the repo root — cold-start instructions written for agents
  • sitevitals.tool.json — machine-readable tool manifest (commands, flags, schemas, exit codes)
  • schemas/ — JSON Schemas for both modes' --json output
  • Exit codes: 0 = score ≥ --min-score (default 70), 1 = below threshold, 2 = error — agents and CI can gate on these directly
  • Safety: report-only, passive checks, secrets never printed or verified live, only package names + versions leave the machine (OSV lookup)

Limits

SiteVitals is a hygiene check, not a penetration test. It will not find application vulnerabilities. It makes sure the front door is locked, the windows are latched, and the alarm is on.
